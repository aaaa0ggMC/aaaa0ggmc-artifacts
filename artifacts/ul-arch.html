Unlimited Life 整合包架构总览 ​

Unlimited Life（UL，暂译「啥都可以」） 是一个 Minecraft 1.12.2 变形主题整合包：以 Metamorph 变形为骨架，玩家通过感染、仪式与任务获取形态，每个形态自带能力、代价与阵营身份。架构上的核心思路是一句话：

一个通用机制核心（morphext）+ 三个第三方适配 patch + 一个内容主模组 + 一个数值层 + 一套离线任务工具链，跑在双运行时上，共享一个 mod 池。

4. morphext 核心（通用机制层） ​

4.1 能力系统 ​

契约与注册表：IAbility（IActiveAbility / IPassiveAbility / IStatefulAbility）→ AbilityRegistry（能力目录 + 临时授予）→ AbilityNetwork（网络）→ ServerAbilityService（服务端执行）→ PlayerAbilityStore（持久化）。内置类型：SimpleAbility / CommandAbility / KeybindAbility（启动时把全部原版键位注册为 keybind:<code> 能力）。

统一释放路径（单人也走逻辑客户端→服务端，不跨侧传对象）：

  1. 1
    入口
    键位/状态页 → ClientAbilityExecutor.activate(ability)
  2. 2
    客户端预检
    被动/解锁/冷却，仅改善交互，不作为授权
  3. 3
    分侧
    ExecutionSide.CLIENT → 本地执行；SERVER → 只发能力 ID
  4. 4
    服务端调度
    AbilityNetwork C2S → 连接上下文取服务端玩家 → 主线程
  5. 5
    分发
    ServerAbilityService 按最长前缀匹配 handler（patch 可用 morphext:jzahar 覆盖核心 morphext:）
  6. 6
    校验 + 执行
    handler 自验 ID/拥有/形态/资源/冷却；核心统一检查 removed > unlocked > 动态条件
  7. 7
    回执
    ActivationResult（SUCCESS/COOLDOWN/LOCKED/UNAVAILABLE/FAILED）经 S2C 回客户端显示
  • 持久化：data/morphext/players/<uuid>.json（schema/owner/unlocked/removed/states/cooldowns），原子写、256 KiB 上限、损坏拒载；登录/重生/维度切换/卷轴操作时同步快照。
  • 冷却语义：服务端以主世界 getTotalWorldTime() 截止值持久化（暂停存档不消耗）；客户端分开维护本地冷却、服务端确认冷却、第三方药效冷却。
  • 临时授予：AbilityRegistry.replaceGrants(source, abilities, player)（来源如 metamorph:current / metamorph:acquired），同来源 ID 差量替换，onGranted/onRevoked 生命周期，不写永久解锁。
  • 卷轴：ability_scroll（普通版清权限留状态）/ ability_scroll_powerful（连框架 states/cooldowns 一起清 + handler.onDataWiped）。
  • UI：GuiInstantWheel 辐射轮盘（默认 G 键、1–8 槽、最多 6 套 Profile、快速/搜索双模式）+ GuiAbilityConfig/GuiAbilityPicker（McLib）+ GuiAbilityStatus 状态页（IStatusSection SPI：addon 可注入只读分节，如尸群队伍面板）。
  • 变身生命周期：MorphAbilityManager 是中枢——变身时装载能力/被动、demorph 卸载，驱动每 tick 被动 update、伤害/药水/属性同步（MorphAttributeSyncHandler，JSON 可覆盖属性）；MorphAiEngine 管变身 dummy 实体的 AI 沙盒（宿主/同盟豁免、危险任务剥离、伴战协同）。

网络协议（频道 morphext，S→C 同步能力数据与形态；阵营关系不同步，纯服务端推导）：

消息方向内容
Request(id) / Reply(id, result)C→S / S→C释放请求（只带能力 id）与结果回执
Snapshot(json)S→C玩家能力数据全量快照（解锁/移除/状态/冷却截止值）；登录/重生/换维度/卷轴时发
SyncRequestC→S请求一次快照（20 tick 限流）
MorphSyncPacketS→C形态同步（AbstractMorph NBT，含动画标记）
CreeperSwellingPacketS→C苦力怕膨胀状态（广播追踪者）
WheelConfigUpdateC→S轮盘配置落盘（16 KB 上限）

4.2 阵营系统（横切行为的统一入口） ​

FactionRegistry（阵营注册 + 类名/接口谓词）→ FactionGraphEngine（parent 继承 + 定向/对称关系图）→ FactionManager（运行时判定）→ MorphImmunityHandler（伤害免疫）+ MixinEntityAIHurtByTarget（AI 侧修复）。数据来自 faction_relations.json（factions / entity_mappings / relations）。

关系阶梯（FactionRelation，解析失败回退 MODERATE）：

关系语义
MEMBER同阵营成员
LORD首领/上级（如 wither → undead）
RELATIVE亲友同盟：不主动攻击，误伤半血以上不还手，受外敌攻击协同反击
MODERATE中立：互不侵犯，被打正常自卫
ENEMY敌对

横切规则全部落在通用入口（修复必须通用，禁止按 ability/模组打补丁）：同阵营免伤、revenge 归属（MorphActionContext 用 ThreadLocal 记动作执行者，解决无 owner DamageSource 让受害者不认账的问题）、召唤物 owner 判定（通用 NBT 标记 ulFollowOwner，不认任何模组私有来源）、suppressMobTarget 清仇恨（只碰已核实 null-safe 的 AI 字段，用原版 removeTask+addTask 语义停用）、MixinEntityAIHurtByTarget 修 alertOthers NPE。阵营规模：核心 18 个（undead/zombie/skeleton/wither/arthropod/…/villager/golem/animal/aquatic/beast，谓词版另含 witch/slime/guardian/pigman/giant）+ patch 注入约 10 个（abyssal/dread/omothol/shadow/shoggoth/antimatter/demon、underworld/crustacean、draconic/insect）。

玩家身份压图：当玩家当前形态携带阵营 FactionPassive（MEMBER/RELATIVE/LORD 三级原型，每阵营自动生成），同族生物按身份等级改判对玩家的态度——MEMBER 被打才反击、RELATIVE 半血以上宽容、LORD 绝对臣服；最具体阵营优先，其次祖先。

4.3 Metamorph 集成 ​

  • 形态 = 实体注册名（minecraft:husk）；形态数据由 Metamorph + vanilla_pack 提供，能力映射由 morphext 的 MorphJsonConfig 全模组扫描。
  • MetamorphIntegration.syncGranted：按当前形态从 AbilityRegistry 取能力临时授予；MorphGrantedAbility 做客户端包装（Metamorph 原生被动只展示不重复触发）。
  • MetamorphServerAbilities：服务端动作执行器（对接 Metamorph IAction），执行期间 MorphActionContext.push 玩家供阵营判定。
  • MetamorphOverwriteHandler：生存模式禁止主动吸收/切换形态——感染与仪式走强制变身不受限。
  • SafeMobActAction + IMobActAdapter：把第三方「原版生物动作」安全桥接到 boss 原生攻击。
  • MorphAbilityDefinition / MorphAnimationRegistry / MorphIcons：动作冷却、动画、图标元数据。

4.4 死亡转化管线 + 数据驱动规则引擎 ​

玩家死亡的唯一入口是 ConversionPipeline（LivingDeathEvent HIGH，仅玩家/服务端），各阶段按 priority 挂载（约定：感染 10 < 规则 20 < 被动 30），任一阶段返回 true 即取消死亡：

conversion_rules.json 的单条规则（四仪式即四条数据；执行序列 = 取消死亡 → MorphFactory 构造形态 → MorphAPI.acquire + morph → 置 1 点血（防埋沙刷血）→ ResidueCleanup 清死法残留 → 扣献祭物 → 标题/粒子/音效 → 记录 ul:ritual/<id> 状态键）：

json
{
  "id": "sand_burial", "line": "zombie_tide", "target": "minecraft:husk",
  "priority": 100,
  "place":  { "dimension": 0, "biomeTypes": ["SANDY"], "nearBlocks": ["minecraft:sand"], "nearRadius": 2, "structureRadius": 32 },
  "death":  { "types": ["inWall"] },
  "state":  { "formCategory": ["ul:undead"], "time": "any", "weather": "any" },
  "consume": [], "title": "…ritual.sand_burial.title"
}

4.5 数据驱动装载 ​

核心 loader 扫描所有已安装模组的 assets/<modid>/morphext/*.json（无路径白名单），config 可覆盖，/morphext reload 热重载：

形态 → 能力包： { "blaze": { "abilities": ["fly", "fire_proof", "faction_nether"], "actions": ["blaze_fireball", "blaze_fire_ring"], "removeAbilities": ["water_allergy"], "damageImmunities": ["inFire", "onFire", "lava", "hotFloor", "fall"], "attackDamage": 6.0 } } 通道：abilities=被动、actions=主动动作、damageImmunities=免伤、hands=手部骨骼

⚠ 命名现状偏差

约定是 patch 能力用 morphext_<modid>: 或 morphext:<mod>_<ability> 前缀；实际只有 morphext:jzahar_banish 合规，其余是 ac_* / quark_* / bop_* / dot_* 裸前缀（Quark/modpack 额外双写 morphext: 键）。数据文件里同一形态用 abyssalcraft:x / abyssalcraft.x 双键兜底。后续规范化时注意兼容。

6. UL 内容层（aaaa0ggmc_ul_modpack） ​

6.1 安卡护符与感染线 ​

ankh_amulet（Baubles AMULET 槽，+2 护甲，固定 UUID 属性修饰符）。「被感染」链路挂在 morphext 转化管线上（InfectionHandler 是 priority 10 的 ConversionStage，不自己监听死亡事件）：

  1. 1
    触发三条件
    种族白名单（human/villager，RaceResolver 判定）× 击杀者属 ul:undead 类别（数据驱动 killer_categories）× 佩戴护符（命中才消耗）
  2. 2
    取消死亡
    ctx.cancelDeath()：无死亡界面、无掉落、无死亡消息
  3. 3
    强制变身
    race_target_forms 固定目标优先（村民→僵尸村民），否则化身为击杀者形态（Metamorph MorphAPI.acquire + morph(force)）
  4. 4
    状态收尾
    回满生命（形态会改写最大生命上限）、粒子/音效/文案、进度「被感染」弹窗
  5. 5
    记录
    感染状态写入 morphext 玩家数据（aaaa0ggmc_ul_modpack:infection）+ 显式种族 ul.race

种族 ≠ 形态：RaceResolver 判定链 = 形态映射（ankh.json race_map）→ 显式记录（morphext states）→ 兜底（human/unknown）。AnkhConfig 分层装载（内置 → config 覆盖 → 5 秒热重载 + /ulpack reload）。

6.3 尸潮与泰坦（zombie_tide 线） ​

  • 尸群领导（技能 ul:horde_leadership，变成任意僵尸族自动授予）：空手右键僵尸族 = 招募（按说服度匹配：低说服度先打残、再低搭腐肉，followCap 人数上限）；潜行右键空气 = 解散；HordeManager（≈883 行）管招募/说服度/屠村/铁傀儡防守；HordeNetwork S2C 队伍快照（5 秒节流 + 变化即推）。
  • 能力：horde_recruit / horde_launch（发动屠村）/ horde_release / titan_slam（震地）经 HordeAbilities 注册进 morphext 能力轮盘。
  • 泰坦：吃「热忱的腐肉」（ItemZealousFlesh，前置 = 尸群领导 + 通关尸潮 + 头顶净空 + 不死者形态）→ TitanFeast 服务端权威变身 minecraft:giant。泰坦代价：移速 -25%、饥饿 ×2、进不去 2 格高、不能睡床。
  • 状态页：B 键 → FollowerStatusSection 走核心 IStatusSection SPI，显示随从/说服度/尸潮状态。

7. 数值层（ul-strength-design） ​

UlStrength.num/integer/flag/tier → DesignRegistry 三层合并（后加载赢）：

  1. 1
    ① 包内默认
    assets/ul_strength_design/ul_strength/defaults.json：tiers 档位表（damage/health/cooldown_seconds/speed × t1..t5）
  2. 2
    ② 模组自带
    所有已安装模组的 assets/<modid>/ul_strength/*.json（ulmodpack 带 zombie_tide.json 兜底）
  3. 3
    ③ 实例覆盖
    config/ul_strength_design/*.json——数值对齐只改这里，不重新构建

每键记录来源（/ulstrength where 可查），ReloadWatcher 每 5 秒轮询 mtime 自动热重载（另有 /ulstrength reload|tiers|get|list）。键名约定 <line>.<system>.<item>（如 zombie_tide.horde.recruit_radius）。

消费边界

数值层的唯一消费者是 ulmodpack 的 zombie 线（HordeManager/Persuasion/TitanFeast 等直接 import）。morphext 核心与 patch 对它零引用——核心能力数值走自己的 morph_abilities.json + MorphExtTuning 常量。两套数值通道是刻意解耦，不是遗漏。

运行时坑（验收时注意）

World.getBiome 在本包不可信（生成层缓存被群系模组改写，恒报 Deep Ocean），真值要读 world.getChunk(pos).getBiome(pos, world.getBiomeProvider())；客户端未加载区块群系读数是 Plains 回退值。LWJGL2 直连 Xvfb 会 GLXBadCurrentWindow（须经 VirtualGL），LWJGL3（Cleanroom）不受影响。HMCL 每次启动清空 natives 目录。Cleanroom 读 modProperties.iconItem，缺了 mods 界面图标品红。
